# README design notes

## English

The documentation follows a practical open-source sequence: purpose and limitations, feature map, prerequisites, installation, reproducible demo, detailed configuration, pitfalls, tests, contributions and license. Every Markdown guide puts its English block before its Chinese counterpart. Code and flags stay identical.

Structure references inspected on GitHub:

- [Best-README-Template](https://github.com/othneildrew/Best-README-Template): installation, usage and contribution navigation.
- [awesome-readme](https://github.com/matiassingers/awesome-readme): task-focused README examples.
- [GitHub README guidance](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes): project purpose, usefulness, getting started and contributor routing.

Only structural ideas were used. No template body, manufactured star count, support contact, demo screenshot or unverified test result is included. Examples use reserved domains and synthetic records. Long instructions live in dedicated guides.

## 中文

文档顺序为：用途和限制、功能映射、前置条件、安装、可复现演示、详细配置、踩坑、测试、贡献和许可。每份 Markdown 的英文完整内容在前，中文对应内容在后；代码和参数一致。

联网核对的结构参考：

- [Best-README-Template](https://github.com/othneildrew/Best-README-Template)：安装、使用与贡献导航。
- [awesome-readme](https://github.com/matiassingers/awesome-readme)：围绕实际任务组织的示例。
- [GitHub README 文档](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes)：用途、价值、入门和贡献入口。

只参考结构，没有复制模板正文，也没有虚构星数、支持联系人、演示截图或未经验证的测试结果。示例使用保留域名和合成记录，详细操作放在独立文档。
